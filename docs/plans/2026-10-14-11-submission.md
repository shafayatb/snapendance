## Steps

Each step ends with its checks; the commit message is suggested.

1. **Release signing** — `build.gradle.kts`: load `rootProject.file("key.properties")` if present,
   add `signingConfigs.release` (`storeFile`, `storePassword`, `keyAlias`, `keyPassword`), use it
   for `release`, else debug; drop the template TODO comments it touches. User runs (outside the
   repo) `keytool -genkey -v -keystore ~/keystores/snapendance-upload.jks -keyalg RSA -keysize 2048
   -validity 10000 -alias upload` and writes `android/key.properties`.
   Checks: `flutter build apk --release` with and without `key.properties`;
   `apksigner verify --print-certs` shows the upload cert (not "Android Debug");
   `git status --ignored` shows the keystore absent and `key.properties` ignored.
   `chore(android): sign release builds from key.properties`
2. **Public-clone hygiene** — S5 link fixes in `AGENTS.md`, `product.md`, task files; S6 path;
   `git grep` for `/Users/`, usernames, emails, IPs, coordinates, API keys; confirm
   `local.properties`, `key.properties`, `*.jks` untracked.
   `docs: make tracked docs safe for a public clone`
3. **Full automated gate** — `flutter analyze`, `flutter test`, `./gradlew testDebugUnitTest`,
   `git diff --check`. No code change expected; a failure becomes its own fix step.
4. **Release run on the A04s** (needs the phone connected and you nearby; recorded in the log):
   install `app-release.apk` over a clean uninstall; Home → Attendance: permissions, set office,
   distance updates, mark within 50 m, blocked beyond 50 m (needs a short walk) and with location
   off; Camera: permission, pinch, slider, preset buttons, flash, tap focus ring, background/return;
   two batches captured and submitted; airplane mode on → uploads wait/fail and keep images →
   airplane off → uploads finish without touching the app; MOCK API failure scenario then Retry.
   Watch for release-only breakage (R8 stripping the WorkManager/plugin classes, the
   `@pragma('vm:entry-point')` dispatcher). Screenshots/GIFs are captured during this run.
5. **Screenshots** — S7 files into `docs/screenshots/` (Home, Attendance out of range, Attendance
   marked, Camera with zoom/focus, Upload Manager with several batch states, MOCK API sheet, two
   GIFs), coordinates redacted, each checked by eye before adding.
   `docs(readme): add app screenshots`
6. **README** — replaces the starter text: (1) title/description; (2) structure and approach:
   combined APK, Flutter feature-first layers (`lib/app`, `lib/features/camera`,
   `lib/features/uploads`: data/domain/presentation), `CameraCubit`, `BatchCubit`,
   `UploadsCubit` summaries, native `AttendanceViewModel` with `StateFlow`, the `navigation`
   method channel, sqflite + WorkManager queue, mock API; (3) AI usage (S8); (4) how to run:
   Flutter 3.44.6 / Dart 3.12.2, JDK 17, Android SDK 37, `flutter pub get`, `flutter run`,
   `flutter build apk --release`, tests, permissions; (5) screenshots; plus the uploads-plan
   README notes (scheduling delays, force-stop, connectivity hint, mock), the APK link
   placeholder filled at step 8, and known limitations from the backlog's deferred table.
   Checks: every link resolves locally; every command copied from what was actually run.
   `docs(readme): document Snapendance for submission`
7. **Task review and task end** — one read-only review agent on the whole branch; confirmed
   in-scope findings fixed as a step; backlog status Done, close the "Release signing and APK
   hosting" open decision, log entry, `FRESH_PROMPT.md`; merge into `develop` with `--no-ff`.
8. **Publish (only on your go-ahead)** — `develop` → `main` `--no-ff`, tag `v1.0.0`, create the
   public repo and push `main`, `develop`, and the tag. The user uploads `snapendance-v1.0.0.apk`
   to Google Drive and shares the link; fill the README's APK link (one commit on `main`, merged
   back into `develop`) and check the link opens from a signed-out browser.
